§01 · The Mental Model

A tree is a recursive shape.

A tree is the simplest structure that contains itself. Every node is a tree. Every left subtree is a tree. Every right subtree is a tree. The whole and the part share a definition — and that single fact is the source of every great tree algorithm.

Linear structures (arrays, lists, stacks, queues) ask you to think in steps. Trees ask you to think in cases: "what is the answer for this node, given the answer for its children?" Once you can phrase that question, the algorithm writes itself.

Interviewers love trees because they reveal whether a candidate is fluent in recursion. The pattern of "solve the subtrees, then combine" is the most-transferable skill in the whole DSA curriculum — it appears unchanged in graphs, DP, divide-and-conquer, and parser design.

The senior signal

Junior candidates write tree code and hope it terminates. Senior candidates name the base case before they write a single line, then describe the recursive contract: "I assume the subcalls return the answer for the subtrees. I combine them into the answer for this node." If you can articulate this — out loud — you have already passed the data structures bar.

i.

Self-Similarity is the Whole Game

A tree problem is solved by trusting the recursive call. Assume your function works on the children. Combine. Return. That is the entire grammar.

ii.

Edges are O(n), Not n²

An n-node tree has exactly n−1 edges. Every traversal visits each edge twice (down + up). Tree algorithms are almost always O(n) — never quadratic by accident.

iii.

The Base Case is null, Not Leaf

The cleanest recursion handles null as the base case, not "leaf." Null means "subtree of size zero, contributes nothing." This makes the leaf case fall out naturally.

iv.

Top-Down vs Bottom-Up is the Big Choice

Top-down: pass info from parent down (path so far, remaining sum). Bottom-up: gather info from children up (height, count, max). 90% of tree problems pick one of these two.

§02 · Anatomy of a Tree Node

Three fields. Infinite shapes.

Every tree problem starts with the same node definition. Internalize it like multiplication. Then learn the three flavors that show up most often in interviews.

# BINARY TREE NODE — the canonical definition
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val   = val
        self.left  = left      # subtree, possibly None
        self.right = right     # subtree, possibly None

# N-ARY TREE — generalized to any number of children
class NTreeNode:
    def __init__(self, val=0, children=None):
        self.val      = val
        self.children = children or []   # list of TreeNodes

# TRIE NODE — every key char points to a child trie
class TrieNode:
    def __init__(self):
        self.children = {}              # dict: char → TrieNode
        self.is_word  = False            # marks end of inserted word

The five tree variants you must recognize on sight

A

Binary Tree

Each node has at most 2 children. The default in interviews. "Binary tree" alone means no ordering invariant — values can be anything.

B

Binary Search Tree

A binary tree where left subtree < node < right subtree. Inorder traversal yields sorted output. Search/insert/delete in O(h).

C

Balanced (AVL / Red-Black)

BST with rotations that keep h = O(log n). You will not implement rotations in an interview, but you must know why they exist.

D

Heap (Complete Binary)

Binary tree filled level-by-level with the max (or min) at the root. Stored as an array. Powers priority queues.

E

Trie (Prefix Tree)

Each edge labeled with a character. Every word is a path from root to a marked node. Powers autocomplete and spell-check.

The "what kind of tree?" question — ask it first

Before writing a line of code, ask: "Is it a BST?" Because if yes, every problem becomes easier — inorder gives sorted, search is O(log n), and the BST property prunes half the tree on each step. The cost of asking is zero. The cost of assuming wrong is twenty minutes.

§03 · The Four Traversals

Four orders. Each unlocks a different problem class.

The order in which you visit nodes determines what you can compute. Preorder processes node before children — natural for serializing a tree. Inorder processes left, then node, then right — yields sorted order on a BST. Postorder processes children before node — natural for "size of subtree" or "height" or anything bottom-up. Level-order processes by depth — natural for "shortest depth" or "rightmost node per level."

FIG. 02 · ANIMATEDFour traversals on the same tree — pick one, watch it light up
[READY]Pick a traversal. Nodes turn forest-green in visit order, with the result list shown below.
# THE FOUR TRAVERSALS — Master these, master tree fluency.

def preorder(node, out):           # root → left → right
    if not node: return
    out.append(node.val)               # PROCESS first
    preorder(node.left, out)
    preorder(node.right, out)

def inorder(node, out):            # left → root → right
    if not node: return
    inorder(node.left, out)
    out.append(node.val)               # PROCESS in middle (sorted on BST!)
    inorder(node.right, out)

def postorder(node, out):          # left → right → root
    if not node: return
    postorder(node.left, out)
    postorder(node.right, out)
    out.append(node.val)               # PROCESS last (after children done)

from collections import deque
def level_order(root):             # BFS, depth by depth
    if not root: return []
    out, q = [], deque([root])
    while q:
        size = len(q)                  # lock in the level boundary
        level = []
        for _ in range(size):
            n = q.popleft()
            level.append(n.val)
            if n.left:  q.append(n.left)
            if n.right: q.append(n.right)
        out.append(level)
    return out
The decision rule: if you need info from children to decide a node — postorder. If you need info from parent to decide a node — preorder. If you need sorted values from a BST — inorder. If the question mentions "depth," "level," or "shortest" — level-order.
The candidate who writes "return helper(root.left) + helper(root.right) + 1" without flinching has already won. Trust the recursion.
— observation from 300+ senior coding interview debriefs

The taxonomy below covers the vast majority of tree questions. When the interviewer states the problem, your first move is to silently classify it. Naming the pattern is half the score.

§05 · Pattern Deep Dive — Top-Down DFS

Pass down what the child needs.

Top-down DFS adds parameters to the recursive call that carry information from the root toward the leaves: the path so far, the remaining sum, the maximum value seen, the depth.

The pattern is identifiable by its signature: the helper takes the node and some accumulated state. The function rarely returns anything meaningful — it usually mutates a result via closure or a list.

This is the right tool when the problem asks "starting from the root, find/count/return all paths or properties that depend on what came before."

The signature tells you the type

If the helper signature is dfs(node, accumulator) — top-down. If it's dfs(node) → some_value — bottom-up. The two are not interchangeable. Choosing the right one in the first 30 seconds is half the battle.

FIG. 03 · ANIMATEDPath Sum — top-down DFS, target = 22
[INIT]Find any root-to-leaf path summing to 22. Watch the recursion descend, backtrack, and find it.
# Path Sum — does ANY root-to-leaf path equal targetSum? — LeetCode 112
def has_path_sum(root, target):
    if not root: return False
    # LEAF — check the running condition
    if not root.left and not root.right:
        return root.val == target
    # INTERNAL — pass remaining sum down
    remaining = target - root.val
    return has_path_sum(root.left,  remaining) or \
           has_path_sum(root.right, remaining)

# Path Sum II — return ALL such paths. Backtracking template.
def path_sum_all(root, target):
    res, path = [], []
    def dfs(node, remaining):
        if not node: return
        path.append(node.val)
        if not node.left and not node.right and remaining == node.val:
            res.append(list(path))                    # COPY the current path
        dfs(node.left,  remaining - node.val)
        dfs(node.right, remaining - node.val)
        path.pop()                                    # BACKTRACK
    dfs(root, target)
    return res

# Sum Root-to-Leaf Numbers — each path forms a number. LeetCode 129.
def sum_numbers(root):
    def dfs(node, current):
        if not node: return 0
        current = current * 10 + node.val
        if not node.left and not node.right: return current
        return dfs(node.left, current) + dfs(node.right, current)
    return dfs(root, 0)
§06 · Pattern Deep Dive — Postorder Return

Trust the children. Combine their answers.

Bottom-up DFS is the most beautiful recursion pattern in the book. The function returns information about its subtree. The parent combines what came back from its children. The base case (null) returns the identity element (0, empty, infinity).

This pattern is recognizable by the helper signature returning a useful value (or a tuple of values). It is the answer to "diameter," "max path sum," "is balanced," "lowest common ancestor," and most "global tree property" questions.

FIG. 04 · ANIMATEDTree Diameter — postorder returns left-height & right-height
[INIT]For each node, compute leftHeight + rightHeight. The maximum across all nodes is the diameter.
# Diameter of Binary Tree — longest path between any two nodes (in EDGES). LC 543.
# Insight: at each node, the candidate diameter "passing through" is left_h + right_h.
def diameter(root):
    best = [0]                                # mutable closure trick
    def height(node):                       # RETURNS height of subtree
        if not node: return 0            # base: empty subtree, height 0
        l = height(node.left)
        r = height(node.right)
        best[0] = max(best[0], l + r)     # diameter through THIS node
        return 1 + max(l, r)              # height to my parent
    height(root)
    return best[0]

# Maximum Path Sum — the boss-fight bottom-up problem. LC 124. HARD.
def max_path_sum(root):
    best = [float('-inf')]
    def gain(node):                         # max DOWNWARD gain from this node
        if not node: return 0
        l = max(0, gain(node.left))           # negative gains: don't take them
        r = max(0, gain(node.right))
        best[0] = max(best[0], node.val + l + r)  # path THROUGH node
        return node.val + max(l, r)         # path to parent (must be linear)
    gain(root)
    return best[0]

# Lowest Common Ancestor — binary tree (no BST property). LC 236.
def lca(root, p, q):
    if not root or root is p or root is q: return root
    l = lca(root.left,  p, q)
    r = lca(root.right, p, q)
    if l and r: return root           # found p and q in different subtrees → I am LCA
    return l or r                       # otherwise, propagate the side that found something
The two-quantity trick: Max Path Sum needs to return the linear gain to the parent but also update a global best for paths "through" each node. The closure pattern (a one-element list best[0] or nonlocal best) handles the second quantity without mutating return shapes. This is the senior-level idiom.
§07 · Pattern Deep Dive — BST

The ordering invariant changes everything.

A BST is a binary tree with a contract: for every node, all values in the left subtree are less, all values in the right subtree are greater. That single rule unlocks a wave of optimizations — search becomes O(h), inorder yields sorted output, and most operations prune at least one subtree per recursive call.

FIG. 05 · ANIMATEDBST Search — pruning in action, target = 14
[INIT]Walk down the BST. Compare target to current value; recurse only on the relevant side.
# BST Search — O(h)
def bst_search(root, target):
    while root:
        if root.val == target: return root
        root = root.left if target < root.val else root.right
    return None

# Validate BST — the trap is "left.val < root.val" alone is INSUFFICIENT.
# You must enforce the bound through the WHOLE subtree.
def is_valid_bst(root):
    def check(node, lo, hi):
        if not node: return True
        if node.val <= lo or node.val >= hi: return False
        return check(node.left, lo, node.val) and check(node.right, node.val, hi)
    return check(root, float('-inf'), float('inf'))

# Kth Smallest in BST — inorder traversal stops at the kth element.
def kth_smallest(root, k):
    stack = []
    while root or stack:
        while root:                       # go all the way left
            stack.append(root)
            root = root.left
        root = stack.pop()
        k -= 1
        if k == 0: return root.val
        root = root.right                  # now go right and repeat

# LCA on a BST — O(h) using ordering, no postorder needed.
def lca_bst(root, p, q):
    while root:
        if p.val < root.val and q.val < root.val: root = root.left
        elif p.val > root.val and q.val > root.val: root = root.right
        else: return root             # split point — this is the LCA
The Validate BST trap: checking only that node.left.val < node.val < node.right.val at each node is wrong — a deeply nested left descendant could be larger than the root and still pass that local check. You must enforce a range (lo, hi) that tightens as you recurse. This is the most common interview gotcha for trees.
§08 · Pattern Deep Dive — Construction

From traversals back to trees. Inverse recursion.

"Build the tree from preorder + inorder." This is the most-asked construction problem. The trick: the first element of preorder is always the root; finding it in the inorder array tells you where the left subtree ends and the right begins.

# Build from preorder + inorder — LC 105.
# Use a hash for O(1) inorder index lookup → overall O(n).
def build_tree(preorder, inorder):
    idx = {v: i for i, v in enumerate(inorder)}
    pre_iter = iter(preorder)            # single global iterator
    def build(lo, hi):                  # inorder range [lo, hi)
        if lo >= hi: return None
        root_val = next(pre_iter)        # preorder gives root first
        root = TreeNode(root_val)
        mid = idx[root_val]              # split point in inorder
        root.left  = build(lo, mid)      # MUST do left before right (preorder!)
        root.right = build(mid + 1, hi)
        return root
    return build(0, len(inorder))

# Sorted Array → Balanced BST — LC 108. The cleaner inverse problem.
def sorted_to_bst(arr):
    def build(lo, hi):
        if lo > hi: return None
        mid = (lo + hi) // 2            # middle element becomes root → balanced
        root = TreeNode(arr[mid])
        root.left  = build(lo, mid - 1)
        root.right = build(mid + 1, hi)
        return root
    return build(0, len(arr) - 1)

# Serialize / Deserialize Binary Tree — LC 297. Classic FAANG senior question.
# Preorder with "#" markers for nulls makes deserialize a single recursion.
class Codec:
    def serialize(self, root):
        out = []
        def go(node):
            if not node: out.append("#"); return
            out.append(str(node.val))
            go(node.left); go(node.right)
        go(root)
        return ",".join(out)

    def deserialize(self, data):
        it = iter(data.split(","))
        def go():
            tok = next(it)
            if tok == "#": return None
            node = TreeNode(int(tok))
            node.left  = go()
            node.right = go()
            return node
        return go()
The senior-level construction insight: a single global iterator over preorder eliminates index bookkeeping. Same for deserialize. This is significantly cleaner than passing index parameters through the recursion. Show this in interviews; it signals fluency.
§09 · The Canon

Fourteen problems. Solve these cold, you are ready.

01 · Maximum Depth of Binary TreeEASY

Prompt: Return the height of a binary tree.

Pattern

Bottom-up DFS. return 1 + max(depth(left), depth(right)), base case 0.

The "Hello World" of recursion. If a candidate cannot write this without thinking, the loop ends here. Drill it until automatic.
02 · Invert Binary TreeEASY

Prompt: Mirror the tree (swap left and right at every node).

Pattern

Recursion. Swap children, recurse on both.

Famous as the question Max Howell (creator of Homebrew) reportedly couldn't solve at Google. Don't be him.
03 · Symmetric TreeEASY

Prompt: Is the tree a mirror of itself?

Pattern

Helper takes two nodes, checks val match, then recurses (a.left, b.right) and (a.right, b.left).

The two-pointer-into-tree variant — a single function with two arguments testing complementary structures. Pattern reused in "same tree," "subtree," and structural-equality checks.
04 · Diameter of Binary TreeEASY

Prompt: Length (in edges) of the longest path between any two nodes.

Pattern

Bottom-up. Return height to parent; update global max with left_h + right_h at each node.

First introduces the "return one quantity, update another via closure" pattern. Templating for max-path-sum.
05 · Validate Binary Search TreeMEDIUM

Prompt: Is the tree a valid BST?

Pattern

Pass (lo, hi) bounds down; tighten on each recursion.

The local-check trap is the most common bug in tree interviews. Always enforce the global range.
06 · Lowest Common Ancestor (Binary Tree)MEDIUM

Prompt: Find the deepest node that is an ancestor of both p and q.

Pattern

Postorder. If left finds something AND right finds something, current node is LCA. Else propagate the non-null side.

A masterpiece of recursion. The function returns "first ancestor found" — but the moment both sides return non-null, the current node IS the answer. Articulate this; it shines.
07 · Binary Tree Level-Order TraversalMEDIUM

Prompt: Return nodes grouped by depth.

Pattern

BFS with queue. size = len(q) at the start of each iteration locks the level boundary.

The "size locking" trick is essential. Variants: zigzag (alternate level direction), right-side view (last node per level), average per level.
08 · Path Sum IIMEDIUM

Prompt: Return all root-to-leaf paths summing to target.

Pattern

Top-down DFS with backtracking. Append-recurse-pop on the path list.

The backtracking template: path.append(v) → recurse → path.pop(). The pop is critical — without it, sibling branches inherit garbage state.
09 · Construct Tree from Preorder + InorderMEDIUM

Prompt: Rebuild the tree given two traversal arrays.

Pattern

Recursion. First preorder element is root; its position in inorder splits left/right subtrees.

Use a hashmap for O(1) inorder lookup → O(n) total. Use a global iterator for preorder. These two tricks turn a clunky recursion into seven lines.
10 · Kth Smallest Element in BSTMEDIUM

Prompt: Return the kth smallest value in a BST.

Pattern

Iterative inorder traversal with a counter. Stop when k reaches 0.

Follow-up: "what if the tree is modified frequently and you need many such queries?" Augment each node with subtree size for O(log n) lookup. That's the staff-level answer.
11 · Serialize and Deserialize Binary TreeHARD

Prompt: Convert tree ↔ string round-trip.

Pattern

Preorder with null markers. Single recursion in each direction.

Asked verbatim at Google, Meta, Amazon, Stripe. The clean version is ~12 lines. Learn it cold.
12 · Binary Tree Maximum Path SumHARD

Prompt: Maximum sum of any path (need not start or end at root).

Pattern

Bottom-up. Helper returns max linear gain to parent; update global max with node.val + left + right.

The "negative subtree → take 0 instead" insight (l = max(0, gain(left))) prevents the algorithm from being dragged down by useless branches.
13 · Implement Trie (Prefix Tree)MEDIUM

Prompt: Design a structure supporting insert, search, startsWith.

Pattern

Tree of dicts (or 26-arrays). Walk character by character, creating nodes as needed.

Foundation for "Word Search II" and "Add and Search Word." Mark is_word on the final node, not just on path existence.
14 · Binary Tree Right Side ViewMEDIUM

Prompt: Return values visible from the right side, top to bottom.

Pattern

BFS, take the last node of each level. Or DFS visiting right first and recording first-seen at each depth.

Two valid solutions; offer both. The DFS variant uses depth as a key into a result dict — elegant and runs in O(n)/O(h).

def solve(root):
    best = [0]                       # or float('-inf'), depending on problem
    def helper(node):
        if not node: return 0      # BASE: identity element
        l = helper(node.left)
