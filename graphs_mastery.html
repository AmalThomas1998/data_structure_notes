§01 · The Mental Model

A graph is the universal data structure.

Every other data structure is a graph in disguise. A linked list is a graph where every node has one outgoing edge. A tree is a graph with no cycles and one root. A grid is a graph where each cell connects to its four neighbors. A dependency map, a road network, a friendship circle, a state machine — all graphs.

Once you see this, the world simplifies. The 200 graph problems on LeetCode are not 200 problems. They are ten patterns, each applied to a different shape of vertex set and edge set. Recognize the pattern, apply the algorithm, finish in twenty minutes.

Interviewers ask about graphs because they reveal whether a candidate can model a real problem. The hardest part is not Dijkstra — it's recognizing that "schedule courses with prerequisites" is a graph problem in the first place.

The senior signal

Junior candidates write graph code when told "build a graph." Senior candidates see the graph hidden inside the problem description. "Each course is a node. Each prerequisite is a directed edge. Can I order the nodes such that every edge points forward? That's topological sort." Translating ambiguous problem statements into vertex-and-edge form is the test.

i.

Vertices and Edges, Nothing Else

A graph is a set V of vertices and a set E ⊆ V×V of edges. Everything else — directed, weighted, cyclic — is a property layered on top. Start by asking which properties apply.

ii.

The Visited Set is Sacred

Unlike a tree, a graph can have cycles. Without a visited set, BFS and DFS will loop forever. The first line of every graph algorithm is visited = set(). Forgetting it is the #1 graph bug.

iii.

BFS = Shortest, DFS = Reachable

BFS on an unweighted graph finds shortest paths in O(V+E). DFS finds connected components, cycles, topological orders. Pick by question: "shortest" → BFS, "reachable / order / cycle" → DFS.

iv.

Weights Change the Algorithm

BFS works only on unweighted (or unit-weighted) graphs. Add weights and you need Dijkstra (non-negative) or Bellman-Ford (negative allowed). This single distinction trips half of all candidates.

§02 · How to Store a Graph

Three representations. Choose by density.

Before any graph algorithm runs, you have to choose how to store the graph. The wrong representation costs an order of magnitude in time and memory. Senior candidates pick deliberately and explain the trade-off.

# 1. ADJACENCY LIST — the default. Sparse graphs. Most interview problems.
from collections import defaultdict
graph = defaultdict(list)
graph[0].append(1)        # edge 0 → 1
graph[1].append(2)        # edge 1 → 2
# Space: O(V + E)   Iterate neighbors of u: O(deg(u))   Edge exists?: O(deg(u))

# 2. ADJACENCY MATRIX — for dense graphs (E ≈ V²) or O(1) edge lookup.
matrix = [[0]*n for _ in range(n)]
matrix[0][1] = 1            # or weight if weighted
# Space: O(V²)   Iterate neighbors: O(V)   Edge exists?: O(1)

# 3. EDGE LIST — when you only iterate edges (Kruskal's MST, Bellman-Ford).
edges = [(0, 1, 7), (1, 2, 3)]   # (u, v, weight)
# Space: O(E)   No fast neighbor lookup — but perfect for sort-by-weight.

The undirected trap

For an undirected graph stored as an adjacency list, every edge appears twice: once in graph[u] as v, and once in graph[v] as u. Forgetting the second insertion is the most common bug in graph construction. Always add both directions for undirected.

§03 · BFS & DFS — The Two Traversals

One queue, one stack. Different answers.

Every graph algorithm is either BFS, DFS, or a generalization of one of the two. Master both — and the difference between them — and you have unlocked 60% of all graph problems.

FIG. 02 · ANIMATEDBFS vs DFS — same graph, different orders
[READY]Source = node A. Watch BFS expand by layer; watch DFS plunge deep.
# BFS — shortest path on UNWEIGHTED graph. O(V+E).
from collections import deque
def bfs(graph, src):
    dist = {src: 0}                        # distance + visited set in one
    parent = {src: None}                    # for path reconstruction
    q = deque([src])
    while q:
        u = q.popleft()
        for v in graph[u]:
            if v not in dist:
                dist[v]   = dist[u] + 1
                parent[v] = u
                q.append(v)
    return dist, parent

# DFS — recursive, finds reachable, detects cycles, builds topo order. O(V+E).
def dfs(graph, src):
    visited = set()
    def go(u):
        visited.add(u)
        for v in graph[u]:
            if v not in visited:
                go(v)
    go(src)
    return visited

# DFS — iterative version, when recursion depth might blow the stack.
def dfs_iter(graph, src):
    visited = set([src])
    stack = [src]
    while stack:
        u = stack.pop()
        for v in graph[u]:
            if v not in visited:
                visited.add(v)
                stack.append(v)
    return visited
The key invariant: add to visited when you enqueue (BFS) or push (DFS), not when you dequeue/pop. Marking on dequeue causes the same node to be added to the queue multiple times, breaking O(V+E). Senior candidates mark on insert. This is a frequently-missed detail.

§05 · Pattern Deep Dive — Topological Sort

Order is just "who depends on whom."

Topological sort answers: "given dependencies, what's a valid order to do things?" Build courses with prerequisites, install packages with dependencies, evaluate spreadsheet cells, link compilation units. All identical underneath.

Two algorithms exist. Kahn's uses in-degree counts and a queue: repeatedly extract a vertex with in-degree 0, decrement its neighbors' in-degrees, repeat. If you can't extract V vertices, there's a cycle.

DFS-based performs a postorder DFS and reverses the result. Conceptually elegant; Kahn's is more intuitive in interviews.

Why Kahn's is a free cycle detector

If at the end of Kahn's algorithm you haven't extracted all V vertices, the remaining ones form a cycle (each has at least one prerequisite among the others). One algorithm, two answers — order and cycle detection. This is why "Course Schedule II" is just topo sort with a check.

FIG. 03 · ANIMATEDKahn's algorithm — extract zero-in-degree, repeat
[INIT]Course graph. Each step: extract a course with 0 remaining prereqs, output it, decrement its dependents.
# Topological Sort — Kahn's algorithm. O(V+E). Detects cycles.
from collections import deque
def topo_sort(n, edges):
    graph = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v in edges:                          # u must come before v
        graph[u].append(v)
        indeg[v] += 1
    q = deque(i for i in range(n) if indeg[i] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in graph[u]:
            indeg[v] -= 1                         # u is "done" — one fewer prereq for v
            if indeg[v] == 0: q.append(v)
    return order if len(order) == n else []   # [] means cycle exists

# DFS-based topo sort — postorder, then reverse. The recursive elegance.
def topo_dfs(n, edges):
    graph = [[] for _ in range(n)]
    for u, v in edges: graph[u].append(v)
    color = [0] * n                              # 0 white, 1 gray (on stack), 2 black
    order = []
    has_cycle = [False]
    def dfs(u):
        if color[u] == 1: has_cycle[0] = True; return
        if color[u] == 2: return             # already finished
        color[u] = 1
        for v in graph[u]: dfs(v)
        color[u] = 2
        order.append(u)                          # POSTORDER!
    for i in range(n): dfs(i)
    return [] if has_cycle[0] else order[::-1]
§06 · Pattern Deep Dive — Union-Find

The data structure that makes "same group?" O(1).

Union-Find (DSU) maintains a partition of elements into disjoint sets, supporting two operations: find(x) returns x's group representative; union(x, y) merges their groups. With path compression and union by rank, both are O(α(n)) — practically constant for any input you'll ever see.

It is the right answer whenever the problem involves incremental connectivity: edges arrive one at a time, and you ask "are these two nodes connected yet?"

FIG. 04 · ANIMATEDUnion-Find — building components edge by edge
[INIT]9 isolated nodes, 9 components. Add edges one by one; watch components merge.
# Union-Find with path compression + union by rank. O(α(n)) per op.
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank   = [0] * n
        self.components = n              # nice for "how many groups?"

    def find(self, x):                  # with path compression
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])  # flatten
        return self.parent[x]

    def union(self, x, y):              # by rank
        rx, ry = self.find(x), self.find(y)
        if rx == ry: return False          # already same — would create cycle
        if self.rank[rx] < self.rank[ry]: rx, ry = ry, rx
        self.parent[ry] = rx
        if self.rank[rx] == self.rank[ry]: self.rank[rx] += 1
        self.components -= 1
        return True

# Number of Connected Components — LC 323. Three lines of logic.
def count_components(n, edges):
    dsu = DSU(n)
    for u, v in edges: dsu.union(u, v)
    return dsu.components

# Redundant Connection — LC 684. The classic union-find application.
def redundant(edges):
    dsu = DSU(len(edges) + 1)
    for u, v in edges:
        if not dsu.union(u, v):
            return [u, v]              # this edge closed the cycle
The senior unlock: Union-Find can replace some BFS/DFS solutions with much cleaner code, especially when the graph is given as an edge list and you only need component info. It's also the right tool for "2D grid → count islands as edges arrive" — a common follow-up that breaks the standard flood-fill solution.
§07 · Pattern Deep Dive — Dijkstra

Greedy + heap. Optimal for non-negative weights.

Dijkstra's algorithm is BFS with a priority queue. Instead of expanding by edge count, it expands by accumulated distance. The vertex closest to the source comes out of the heap first; once popped, its distance is final.

The proof of optimality rests on one fact: with non-negative weights, a vertex's shortest distance cannot improve once it's the heap's minimum. If it could, some other vertex must have a shorter path to it — but that vertex would have been popped first.

FIG. 05 · ANIMATEDDijkstra from A — heap-driven shortest path
[INIT]Source A. dist[A]=0, others ∞. Pop closest, relax its edges, repeat.
# Dijkstra's algorithm. O((V+E) log V) with a binary heap.
import heapq
def dijkstra(graph, src, n):
    dist = [float('inf')] * n
    dist[src] = 0
    heap = [(0, src)]                         # (distance, vertex)
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]: continue            # stale entry — skip
        for v, w in graph[u]:                # neighbors with edge weight
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(heap, (nd, v))
    return dist

# Reconstruct the actual path — track predecessors.
def dijkstra_path(graph, src, dst, n):
    dist = [float('inf')] * n
    prev = [None] * n
    dist[src] = 0
    heap = [(0, src)]
    while heap:
        d, u = heapq.heappop(heap)
        if u == dst: break                  # early exit when target popped
        if d > dist[u]: continue
        for v, w in graph[u]:
            if d + w < dist[v]:
                dist[v] = d + w
                prev[v] = u
                heapq.heappush(heap, (dist[v], v))
    # walk back from dst
    path = []
    cur = dst
    while cur is not None:
        path.append(cur)
        cur = prev[cur]
    return path[::-1]
The "stale entry" trick: Python's heapq doesn't support decrease-key, so we leave outdated entries in the heap and skip them on pop with if d > dist[u]: continue. This is the canonical idiom — write it in your sleep. The alternative (a custom indexed priority queue) is rarely worth the complexity in interviews.
§08 · Pattern Deep Dive — Grids as Graphs

A grid is a graph in disguise.

Half of all graph interview problems are presented as 2D grids. Each cell is a vertex; edges go to its 4 (or 8) neighbors. Walls/obstacles are missing edges. Once you make this translation, all the graph algorithms apply unchanged.

# Number of Islands — LC 200. Connected components on a grid.
def num_islands(grid):
    if not grid: return 0
    R, C = len(grid), len(grid[0])
    count = 0
    def dfs(r, c):
        if r < 0 or r >= R or c < 0 or c >= C or grid[r][c] != '1':
            return
        grid[r][c] = '#'            # mark visited in-place — saves O(V) memory
        for dr, dc in [(-1,0),(1,0),(0,-1),(0,1)]:
            dfs(r+dr, c+dc)
    for r in range(R):
        for c in range(C):
            if grid[r][c] == '1':
                count += 1
                dfs(r, c)
    return count

# Shortest path on grid with obstacles — BFS, O(R·C).
from collections import deque
def shortest_path(grid, src, dst):
    R, C = len(grid), len(grid[0])
    q = deque([(*src, 0)])
    seen = {src}
    while q:
        r, c, d = q.popleft()
        if (r, c) == dst: return d
        for dr, dc in [(-1,0),(1,0),(0,-1),(0,1)]:
            nr, nc = r+dr, c+dc
            if 0<=nr<R and 0<=nc<C and grid[nr][nc] != '#' and (nr,nc) not in seen:
                seen.add((nr, nc))
                q.append((nr, nc, d+1))
    return -1                                # unreachable
The four directions idiom: [(-1,0),(1,0),(0,-1),(0,1)] — up, down, left, right. Memorize the tuple. For diagonals, add [(-1,-1),(-1,1),(1,-1),(1,1)]. Saves time in every grid problem.
§09 · The Canon

Fourteen problems. Solve these cold, you are ready.

01 · Number of IslandsMEDIUM

Prompt: Count connected regions of '1's in a 2D grid (4-neighbor connectivity).

Pattern

Connected components on a grid. DFS or BFS from each unvisited '1'.

In-place marking ('1' → '#') saves O(R·C) auxiliary memory. Mention this — it shows you think about space, not just correctness.
02 · Clone GraphMEDIUM

Prompt: Deep-copy an undirected graph given a starting node.

Pattern

BFS or DFS with a hashmap {original → clone}. Two passes (or interleave clone-creation with traversal).

Single-pass version: when you visit a node, look up or create its clone, then for each neighbor look up or create theirs and link. The hashmap doubles as the visited set.
03 · Course ScheduleMEDIUM

Prompt: Given prerequisites, can all courses be finished?

Pattern

Cycle detection on directed graph. Topo sort succeeds iff no cycle.

Kahn's is the cleaner answer. If the topo order has fewer than n vertices, there's a cycle. Two algorithms in one.
04 · Course Schedule IIMEDIUM

Prompt: Return any valid course order, or empty if impossible.

Pattern

Topological sort. Kahn's directly outputs the order.

The natural follow-up to Course Schedule. The same algorithm — just keep the queue's pop order.
05 · Word LadderHARD

Prompt: Shortest transformation from beginWord to endWord, changing one letter at a time, with each intermediate in a dictionary.

Pattern

BFS on an implicit graph. Each word is a vertex; edges connect words differing by one letter.

The performance trick: build neighbor templates like "h*t" mapping to all matching words. This avoids comparing every pair of words. Bidirectional BFS halves the explored space — staff-tier signal.
06 · Network Delay TimeMEDIUM

Prompt: Signal travels through a network; return time for all nodes to receive it, or -1.

Pattern

Dijkstra from the source; answer is max(dist), or -1 if any is infinity.

Direct Dijkstra application. The "max of all distances" twist tests whether you understand what Dijkstra returns (distance to every node, not just one).
07 · Cheapest Flights Within K StopsMEDIUM

Prompt: Cheapest path from src to dst with at most k stops.

Pattern

Modified BFS or Bellman-Ford limited to k+1 iterations. Dijkstra works only with state augmentation: (cost, node, stops_left).

The "k stops" constraint breaks vanilla Dijkstra (visited-once invariant fails). Bellman-Ford for exactly k+1 rounds is the cleaner answer. State this trade-off — it earns points.
08 · Redundant ConnectionMEDIUM

Prompt: Given a tree (n nodes, n−1 edges) plus one extra edge, find the extra.

Pattern

Union-Find. Add edges in order; the first one whose endpoints are already connected is the answer.

Direct Union-Find application — three lines of logic. The textbook example for why DSU is in your toolkit.
09 · Accounts MergeMEDIUM

Prompt: Merge accounts sharing any email into one.

Pattern

Union-Find on email indices, with hashmap from email → account-index.

A messy real-world problem that exposes whether you can model: "emails are nodes, sharing-an-account is an edge, components are merged accounts." Modeling clarity matters more than the code.
10 · Pacific Atlantic Water FlowMEDIUM

Prompt: Find cells from which water can flow to both oceans.

Pattern

Reverse BFS/DFS from each ocean's edge inward. Cells reachable from both are the answer.

The reversal is the trick. Naive forward search from each cell is O(R²C²); reverse is O(R·C). Always ask "can I run this backward?" on grid problems.
11 · Is Graph Bipartite?MEDIUM

Prompt: Can the vertices be split into two sets with all edges crossing between them?

Pattern

2-coloring via BFS or DFS. If a neighbor has the same color as you, not bipartite.

Don't forget disconnected components — run the check from every uncolored vertex. This is a common "one test case fails" debugging fix.
12 · Min Cost to Connect All PointsMEDIUM

Prompt: Connect all points with minimum total Manhattan distance.

Pattern

Minimum Spanning Tree. Kruskal (sort all n² edges, Union-Find) or Prim (heap from any vertex).

For dense graphs (every pair is an edge), Prim with adjacency-matrix is O(V²) and beats Kruskal's O(E log E) = O(V² log V). State this; it's the senior consideration.
13 · Alien DictionaryHARD

Prompt: Given a sorted list of words in an alien language, recover the alphabet order.

Pattern

Topo sort. Build directed edges from comparing adjacent word pairs (first differing char gives a precedence).

Edge cases: prefix relationships ("abc" before "ab" is invalid); duplicate edges; characters appearing only in one word still need to be in the result. This is the staff-level test.
14 · Critical Connections in a NetworkHARD

Prompt: Find all bridges (edges whose removal disconnects the graph).

Pattern

Tarjan's bridge-finding via DFS with discovery times and low-link values.

A staff-tier algorithm. low[v] = min(low[v], disc[u]) for back edges; an edge (u,v) is a bridge iff low[v] > disc[u]. If you can derive this on the spot, you're ready for L6+ loops.

from collections import deque
def bfs(graph, src):
    seen = {src}                          # mark on insert!
    q = deque([(src, 0)])             # (node, distance)
    while q:
