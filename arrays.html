§01 · The Mental Model

Arrays are the bedrock. Everything else is a clever lie.

An array is a contract with the memory bus: "Give me N units of contiguous space, and I will tell you the address of any element with one multiplication and one addition." That arithmetic — base + i × stride — is the most efficient lookup in computing. It is so cheap that the CPU does it without breathing.

Hash maps, dynamic arrays, strings, heaps, hash sets, ring buffers, even the call stack — all of these are arrays in disguise, with bookkeeping layered on top. To master arrays is to understand the substrate.

Interviewers love arrays not because they are exotic, but because they are unforgiving. There is nowhere to hide an O(n²) when an O(n) exists. The candidate who reaches for a nested loop on a "find pair" problem is the candidate who does not get the offer.

Why this chapter is different

Arrays test something subtler than other DS questions: the ability to think in indices, not just values. The best candidates manipulate i and j like instruments — they know exactly what every pointer represents at every line. A candidate who narrates their loop invariants will outrank a candidate who writes correct code silently. Index discipline is the senior signal.

i.

Contiguity is the Superpower

Elements sit next to each other in RAM. The CPU prefetcher loves you. A linear scan over an array is roughly 10× faster than the same scan over a linked list — even though both are O(n).

ii.

Indexing is Arithmetic, Not Lookup

There is no "find element 47." There is only arr + 47×8. This is why arr[i] is O(1) — it's literally a single CPU instruction.

iii.

Insert is Shifting in Disguise

Inserting at position k requires shifting n−k elements rightward. The cost is hidden, but it's there. This is the entire reason linked lists exist.

iv.

Sorted Arrays Are a Different Beast

The moment an array is sorted, binary search and two-pointer techniques unlock O(log n) and O(n) algorithms that no unsorted version permits. Always ask: is this sorted?

§02 · Anatomy of an Array

Static, dynamic, multi-dim. Three flavors, three trade-offs.

Every interview problem assumes one of three array types. Knowing which one you're handed — and which one to ask for — is the first 30 seconds of any array question.

# 1. STATIC ARRAY — fixed size, contiguous (the platonic ideal)
int arr[10];                  # C/C++/Java primitives
arr = [0] * 10                # Python — actually a list, but 1D fixed-size feel

# 2. DYNAMIC ARRAY — auto-resizing (Python list, Java ArrayList, C++ vector)
arr = []
arr.append(5)               # O(1) amortized — capacity doubles when full
arr.pop()                    # O(1)
arr.insert(0, 99)            # O(n) — shifts everything right!

# 3. MULTI-DIMENSIONAL — arrays of arrays (matrices, grids)
grid = [[0] * cols for _ in range(rows)]   # row-major
grid[r][c] = 1             # access — still O(1)

The amortization argument you must know

When a Python list is full and you call append, the runtime allocates a new array (typically 1.5× or 2× the current size), copies all elements, and frees the old one. That copy is O(n).

Yet we say append is O(1) amortized. Why? Because over n appends, you only resize log₂(n) times, and the total copying work is 1 + 2 + 4 + ... + n ≈ 2n. Divide by n and you get O(1) per operation on average.

This is the amortized analysis argument. Senior interviewers will probe this. Be ready.

The growth factor wars

Python uses ~1.125×, Java ArrayList uses 1.5×, C++ std::vector uses 2×. Smaller factors save memory but trigger more resizes; larger factors waste up to 50% RAM in the worst case but copy less. Real engineering is full of these dials. If asked, the "right" answer is 1.5× — it lets freed memory be reused on subsequent reallocations, while 2× cannot.

Operation cheat sheet

# 1. INSERT AT INDEX i — O(n), shifts arr[i..end] right
def insert_at(arr, i, val):
    arr.append(None)             # grow by one
    for j in range(len(arr)-1, i, -1):
        arr[j] = arr[j-1]        # shift right
    arr[i] = val

# 2. DELETE AT INDEX i — O(n), shifts arr[i+1..end] left
def delete_at(arr, i):
    for j in range(i, len(arr)-1):
        arr[j] = arr[j+1]        # shift left
    arr.pop()

# 3. SWAP — O(1), the workhorse of in-place algorithms
def swap(arr, i, j):
    arr[i], arr[j] = arr[j], arr[i]   # Python tuple-swap, no temp needed

# 4. REVERSE IN PLACE — O(n) time, O(1) space
def reverse(arr):
    l, r = 0, len(arr)-1
    while l < r:
        arr[l], arr[r] = arr[r], arr[l]
        l += 1; r -= 1

# 5. ROTATE BY k — the THREE-REVERSE TRICK. Senior signal.
def rotate(arr, k):
    n = len(arr); k %= n
    reverse(arr[0:n])           # reverse all
    reverse(arr[0:k])           # reverse first k
    reverse(arr[k:n])           # reverse the rest
    # [1,2,3,4,5,6,7] k=3 → [7,6,5,4,3,2,1] → [5,6,7,4,3,2,1] → [5,6,7,1,2,3,4] ✓
The three-reverse trick for rotation is one of the most-loved interview answers. It uses O(1) extra space where the naive solution uses O(k). Internalize it.

§05 · Pattern Deep Dive — Two Pointers

Two indices. Quadratic problems become linear.

The two-pointer technique is what separates an O(n²) brute force from an O(n) elegant solution. The core idea: place two indices, move them based on a condition, never backtrack.

Two flavors dominate. Opposite ends: l=0, r=n-1, walk inward — solves "two sum sorted," "container with most water," "trapping rain water." Same direction: slow, fast with fast leading — solves "remove duplicates in place," "move zeros."

The unlock is recognizing when monotonicity exists: a quantity that only goes up or only goes down as you advance. That monotonicity justifies "I never need to look back."

The litmus test

Ask: "if I move pointer A inward, can I prove pointer B should not move backward?" If yes, two pointers works. If no, you need something else (likely sliding window or hash).

[INIT]Sorted array. Two pointers from both ends. Find pair summing to target.
# Two-Sum on a SORTED array — O(n), O(1)
def two_sum_sorted(arr, target):
    l, r = 0, len(arr) - 1
    while l < r:
        s = arr[l] + arr[r]
        if s == target:   return [l, r]
        elif s < target:  l += 1     # sum too small → grow it
        else:              r -= 1     # sum too big   → shrink it
    return []

# Container With Most Water — LeetCode 11. The classic.
def max_area(heights):
    l, r = 0, len(heights) - 1
    best = 0
    while l < r:
        h = min(heights[l], heights[r])
        best = max(best, h * (r - l))
        # move the SHORTER side — moving the taller can never improve area
        if heights[l] < heights[r]: l += 1
        else:                       r -= 1
    return best

# Remove Duplicates In Place — fast/slow pointer variant. O(n), O(1).
def remove_dupes(arr):
    if not arr: return 0
    slow = 0
    for fast in range(1, len(arr)):
        if arr[fast] != arr[slow]:
            slow += 1
            arr[slow] = arr[fast]
    return slow + 1          # length of unique prefix
§06 · Pattern Deep Dive — Sliding Window

A window that breathes. One pass. Linear.

The sliding window is two pointers' more sophisticated cousin. Instead of converging, both pointers move rightward: right expands the window to admit new elements; left contracts it to evict elements when an invariant is violated.

The unlock: identify what makes a window "valid" (e.g., "all distinct chars," "sum ≥ k," "at most 2 distinct"). Expand greedily, contract reluctantly.

FIG. 04 · ANIMATEDLongest substring with no repeating characters
[INIT]String "abcabcbb". Window expands right; shrinks left when duplicate found.
# Longest substring without repeating characters — O(n), O(min(n,Σ))
def longest_unique(s):
    seen = {}
    left = best = 0
    for right, ch in enumerate(s):
        if ch in seen and seen[ch] >= left:
            left = seen[ch] + 1     # jump past the dupe
        seen[ch] = right
        best = max(best, right - left + 1)
    return best

# Minimum window substring — Hard. O(|s|+|t|).
def min_window(s, t):
    from collections import Counter
    need = Counter(t)
    have = {}
    formed = 0; required = len(need)
    l = 0; best = (float('inf'), 0, 0)
    for r, ch in enumerate(s):
        have[ch] = have.get(ch, 0) + 1
        if ch in need and have[ch] == need[ch]:
            formed += 1
        while formed == required:               # try to shrink
            if r - l + 1 < best[0]:
                best = (r - l + 1, l, r)
            have[s[l]] -= 1
            if s[l] in need and have[s[l]] < need[s[l]]:
                formed -= 1
            l += 1
    return "" if best[0] == float('inf') else s[best[1]:best[2]+1]
The pattern in one sentence: for each right, expand the window; while the window is invalid (or now optimal), advance left; record the answer.
§07 · Pattern Deep Dive — Prefix Sum

Pay O(n) once. Answer infinitely many range queries in O(1).

Prefix sum is a precomputation trick: define P[i] = arr[0] + arr[1] + … + arr[i-1], with P[0] = 0. Then the sum of any range [l..r] is just P[r+1] − P[l]. One subtraction. O(1).

FIG. 05 · INTERACTIVEPrefix sum — range query in O(1)
[READY]Pick l and r, then "Query Range" to see P[r+1] − P[l] in action.
# Build prefix sum array once — O(n)
def build_prefix(arr):
    P = [0] * (len(arr) + 1)
    for i, v in enumerate(arr):
        P[i+1] = P[i] + v
    return P

# Query sum of arr[l..r] inclusive — O(1)
def range_sum(P, l, r):
    return P[r+1] - P[l]

# Subarray Sum Equals K — LeetCode 560. The killer combo: prefix + hash.
# Insight: number of subarrays ending at i with sum=k
#   == number of prefix sums equal to (running_sum - k) seen so far.
def subarray_sum_k(arr, k):
    count = running = 0
    seen = {0: 1}                    # empty prefix has sum 0, count once
    for v in arr:
        running += v
        count   += seen.get(running - k, 0)
        seen[running] = seen.get(running, 0) + 1
    return count
The combo that wins interviews: prefix sum + hashmap. Whenever a problem asks "how many subarrays satisfy sum-related property X," reach for this duo first. It transforms O(n²) brute force into O(n) every time.
§08 · Pattern Deep Dive — Binary Search

Halve. Halve. Halve.

Binary search is the most under-recognized pattern in competitive interviews. Most candidates know it for sorted arrays. Few realize it works on any monotonic predicate — including the answer space itself ("binary search the answer").

FIG. 06 · ANIMATEDBinary search on a sorted array
[INIT]Sorted array. l=0, r=n−1. Each step halves the search space.
# Canonical binary search — find target index, or -1
def binary_search(arr, target):
    l, r = 0, len(arr) - 1
    while l <= r:
        m = (l + r) // 2           # in C/Java prefer l + (r-l)//2 to avoid overflow
        if arr[m] == target: return m
        elif arr[m] < target: l = m + 1
        else:                 r = m - 1
    return -1

# Find FIRST index where predicate becomes true (lower_bound).
# This is the template for 80% of "find smallest valid X" problems.
def lower_bound(lo, hi, ok):
    while lo < hi:
        m = (lo + hi) // 2
        if ok(m): hi = m            # predicate satisfied → search left
        else:     lo = m + 1
    return lo

# Search in Rotated Sorted Array — LeetCode 33. The classic L4/L5 problem.
def search_rotated(arr, target):
    l, r = 0, len(arr) - 1
    while l <= r:
        m = (l + r) // 2
        if arr[m] == target: return m
        if arr[l] <= arr[m]:                  # left half sorted
            if arr[l] <= target < arr[m]: r = m - 1
            else:                          l = m + 1
        else:                                 # right half sorted
            if arr[m] < target <= arr[r]: l = m + 1
            else:                          r = m - 1
    return -1
Senior unlock — "binary search the answer": when the problem asks for the minimum/maximum value satisfying some property, and that property is monotonic in the value, binary search the value space. Examples: "min capacity to ship in D days," "split array largest sum," "kth smallest in matrix." The trick converts an O(n²) DP into O(n log V).
§09 · The Canon

Twelve problems. Solve these cold, you are ready.

01 · Two SumEASY

Prompt: Given an array and a target, return indices of the two numbers that add to target.

Pattern

Hash for O(1) lookup. Walk once; for each v, check if target − v was seen before.

The most-asked first interview question on the planet. Brute force is O(n²); the hash unlock is O(n)/O(n). If sorted, two-pointer gives O(n)/O(1) — be ready to discuss the trade.
02 · Best Time to Buy and Sell StockEASY

Prompt: One buy, one sell, return max profit. Can't sell before buying.

Pattern

Greedy + single pass. Track min_so_far and best_profit.

Three follow-ups exist (II, III, IV — multiple transactions, with cooldown, with fee). Each is a DP. If the interviewer escalates, you've entered DP territory.
03 · Maximum Subarray (Kadane's)MEDIUM

Prompt: Find the contiguous subarray with the largest sum.

Pattern

Greedy / 1-D DP. Maintain cur = max(v, cur + v); track global max.

Kadane's is the canonical answer. The DP recurrence: dp[i] = max ending at i = max(arr[i], dp[i-1] + arr[i]). Mention the recurrence — interviewers love when you bridge greedy and DP.
04 · 3SumMEDIUM

Prompt: Find all unique triplets that sum to zero.

Pattern

Sort + two-pointer. Fix i, then two-pointer the rest. Skip duplicates carefully.

The duplicate-skipping is where most candidates fumble. Skip i if arr[i]==arr[i-1]; skip l after success while arr[l]==arr[l+1]; skip r similarly. Three skips. Drill them.
05 · Container With Most WaterMEDIUM

Prompt: Pick two heights forming the container holding the most water.

Pattern

Two pointers. Always move the shorter side inward.

The proof: moving the taller side cannot improve area (height capped by shorter, width decreases). Articulate this — it's the senior-level insight.
06 · Trapping Rain WaterHARD

Prompt: Given heights, compute total trapped rainwater.

Pattern

Two pointers + max-from-each-side reasoning. O(n)/O(1).

Three valid approaches — DP arrays (O(n)/O(n)), monotonic stack (O(n)/O(n)), two-pointer (O(n)/O(1)). Walk through all three; deliver two-pointer. That's a staff-level signal.
07 · Product of Array Except SelfMEDIUM

Prompt: Return array where ans[i] = product of all elements except arr[i]. No division.

Pattern

Prefix product + suffix product, fused into two passes with O(1) extra.

First pass: store left-products in ans. Second pass: multiply by running right-product. The "no division" constraint is what makes this elegant.
08 · Subarray Sum Equals KMEDIUM

Prompt: Count contiguous subarrays whose sum equals k.

Pattern

Prefix sum + hashmap. Count how often running_sum − k has appeared.

The "+1 for the empty prefix" initialization (seen = {0: 1}) is the bug everyone hits. It accounts for subarrays starting from index 0.
09 · Search in Rotated Sorted ArrayMEDIUM

Prompt: A sorted array, rotated at unknown pivot. Search for target in O(log n).

Pattern

Modified binary search. Determine which half is sorted at each step; check whether target lies in that half.

The boundary condition arr[l] <= arr[m] (not <) handles duplicates and the case where l == m. Easy to get wrong; rehearse it.
10 · Longest Substring Without Repeating CharactersMEDIUM

Prompt: Length of longest substring with all distinct characters.

Pattern

Sliding window + hashmap of last-seen index.

Use last-seen index, not boolean. When you see a duplicate, jump left to last_seen + 1 — but only if last_seen ≥ left (otherwise it's outside the current window).
11 · Median of Two Sorted ArraysHARD

Prompt: Find the median of two sorted arrays in O(log(min(m,n))).

Pattern

Binary search on the smaller array's partition. Hard to derive; expected for L5+ at FAANG.

Most interviewers accept O(m+n) merge as a baseline. The log solution requires partitioning so left halves combined have ⌈(m+n)/2⌉ elements. If you can articulate the partition invariant, you're at staff level.
12 · First Missing PositiveHARD

Prompt: Given an unsorted array, find the smallest missing positive integer in O(n) / O(1).

Pattern

Cyclic sort / index-as-hash. Place each value v in [1..n] at index v−1. Then scan for first index where arr[i] != i+1.

The constraint forces O(1) extra space — no hashmap, no extra array. The trick is realizing the answer is always in [1..n+1], so values outside that range are noise.

The reversal-rotation trick — write this from memory tonight:

# Rotate array right by k — three reverses, O(1) extra space
def rotate(arr, k):
    n = len(arr); k %= n
    arr.reverse()                  # whole array
    arr[:k] = reversed(arr[:k])    # first k
    arr[k:] = reversed(arr[k:])    # rest
