§01 · The Mental Model

Two policies. One memory.

Stacks and queues are not data structures. They are discipline. Underneath, both are arrays (or linked lists). What separates them is a single rule about which end you're allowed to touch.

A stack says: last in, first out. The most recent thing you saved is the only thing you can retrieve. It is the structure of recursion, of undo, of "what was I doing before this?"

A queue says: first in, first out. The oldest thing waiting gets served next. It is the structure of fairness, of breadth-first exploration, of buffering.

Interviewers ask about them because the discipline itself — the recognition that "I should only ever look at the top" or "I should drain from the front" — is the test. The data structure is trivial; the seeing of when to use it is the senior signal.

Why they appear together

Stacks and queues are duals. Whatever recursion does (DFS, depth-first), an explicit stack can do iteratively. Whatever level-order does (BFS, breadth-first), a queue powers. Master both and you can convert any tree or graph traversal between recursive and iterative — a request that comes up in nearly every senior loop.

i.

LIFO is About Memory of Now

A stack remembers what's "still open" — open brackets, function calls in flight, partial expressions. Pop = "I'm done with the most recent thing."

ii.

FIFO is About Order of Then

A queue preserves arrival order. It is the only DS that gives you "process things in the order they showed up" without sorting.

iii.

Both Are O(1) at Their Active End

Push, pop, peek, enqueue, dequeue — every primitive is constant time. This is why they show up in tight inner loops where everything else would be too slow.

iv.

The Hidden Pattern is "Pending"

Both structures hold things that are not yet resolved. Stack: "I haven't found this open bracket's match." Queue: "I haven't visited this neighbor yet." Once you see "pending," you see the structure.

§02 · Anatomy of a Stack

The simplest powerful container.

A stack is an array with two methods removed. You can push on the top and pop from the top. That's the entire interface. The mental image is a stack of plates — you only ever touch the topmost one.

# In Python, a list IS a stack. No special class needed.
stack = []
stack.append(1)         # push        → [1]
stack.append(2)         # push        → [1, 2]
stack.append(3)         # push        → [1, 2, 3]
top = stack[-1]        # peek (3)    no mutation
val = stack.pop()       # pop  (3)    → [1, 2]
empty = not stack       # True if []

# Common idiom: process while non-empty
while stack:
    item = stack.pop()
    # ... do work, possibly push new items back ...

Stack as memory-of-pending — the unifying intuition

Every great stack algorithm shares a structure: "I keep things on the stack until I find the thing that resolves them, then I pop and process."

For parentheses, you keep open brackets until you see their match. For Next Greater Element, you keep candidates that haven't found a "greater" yet. For function calls, you keep frames until they return.

If you can identify "what does the stack hold, and what triggers a pop?" you have solved 90% of stack problems.

The stack-of-indices trick

For monotonic-stack problems, store indices, not values. The index lets you compute distances ("how far back was the previous greater element?"), retrieve the value via arr[i], and remember position simultaneously. Storing values throws information away. Senior candidates store indices by default.

§03 · Anatomy of a Queue

The fairness structure.

A queue admits at one end and serves from the other. The implementation is where it gets interesting: a naive list-based queue with arr.pop(0) is O(n), because every dequeue shifts every remaining element. The interview-correct implementation uses either a linked list with head/tail pointers or a ring buffer with two indices.

# NEVER do this in production — pop(0) is O(n)
queue = []
queue.append(1)
queue.pop(0)              # O(n) — shifts everything left

# DO use collections.deque — O(1) on both ends
from collections import deque
q = deque()
q.append(1)             # enqueue at rear, O(1)
q.append(2)
val = q.popleft()        # dequeue from front, O(1)

# Common BFS skeleton
def bfs(start):
    q = deque([start])
    seen = {start}
    while q:
        node = q.popleft()
        for nb in neighbors(node):
            if nb not in seen:
                seen.add(nb)
                q.append(nb)

The three queue variants you must know

A

Plain Queue

FIFO. Enqueue rear, dequeue front. The workhorse of BFS. Implemented with collections.deque.

B

Deque (Double-Ended)

Push and pop on both ends. The secret weapon for sliding-window-maximum, palindrome checks, and any "monotonic queue" problem.

C

Priority Queue (Heap)

Highest- (or lowest-) priority element comes out first, regardless of insertion order. Powers Dijkstra, A*, K-way merge, top-K. This is a different structure — covered in the heap chapter.

§05 · Pattern Deep Dive — Monotonic Stack

The pattern that crushes quadratic problems.

The monotonic stack is the most under-recognized pattern in coding interviews. It's the difference between O(n²) brute force and O(n) elegance on a wide class of "for each element, find some related element" problems.

The rule: maintain a stack of indices such that the corresponding values are strictly increasing (or decreasing) from bottom to top. When a new element violates the monotonicity, pop until it doesn't — and at each pop, you have just discovered the popped element's "next greater" (or smaller).

The amortized argument: each index is pushed once and popped at most once, so the total work is O(n) — even though the inner pop-loop looks like it could be O(n²).

The trigger phrase

If a problem asks for "the next/previous greater/smaller element", or "the nearest taller building to the right", or "largest rectangle" — it is a monotonic stack problem. Pattern-match instantly. Don't even consider brute force.

FIG. 04 · ANIMATEDNext Greater Element — monotonic decreasing stack
[INIT]Array [2, 1, 4, 3, 5]. For each i, find the next greater element using a monotonic decreasing stack of indices.
# Next Greater Element — for each i, find arr[j] > arr[i] with smallest j > i.
# Pattern: monotonic DECREASING stack of indices.
def next_greater(arr):
    n = len(arr)
    res = [-1] * n
    stack = []                                # stack of INDICES, values monotonically decreasing
    for i, v in enumerate(arr):
        while stack and arr[stack[-1]] < v:
            res[stack.pop()] = v              # v is the next greater for that popped idx
        stack.append(i)
    return res
# [2, 1, 4, 3, 5]  →  [4, 4, 5, 5, -1]

# Largest Rectangle in Histogram — LeetCode 84. The boss-fight problem.
def largest_rect(heights):
    stack = []          # indices, monotonically INCREASING heights
    best = 0
    heights = heights + [0]    # sentinel forces final flush
    for i, h in enumerate(heights):
        while stack and heights[stack[-1]] > h:
            top = stack.pop()
            height = heights[top]
            width = i if not stack else i - stack[-1] - 1
            best = max(best, height * width)
        stack.append(i)
    return best
The width formula: when a bar at top is popped, its rectangle extends rightward to i (where height drops) and leftward to stack[-1] + 1 (just past the next-smaller-on-the-left). Hence width = i − stack[-1] − 1. Internalize this — it's the heart of histogram problems.
§06 · Pattern Deep Dive — Parentheses

The simplest genuinely useful stack pattern.

Bracket-matching is the "Hello World" of stacks, but the variants — minimum removals, longest valid substring, generation of all valid combinations — quickly escalate to medium and hard. Master the base case, then extend.

FIG. 05 · ANIMATEDValid Parentheses — push openers, pop on closers
[INIT]Input "([{}])". Push openers; on a closer, pop and verify match.
# Valid Parentheses — LeetCode 20
def is_valid(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in s:
        if ch in pairs:                              # closer
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:                                       # opener
            stack.append(ch)
    return not stack                              # empty = perfectly balanced

# Longest Valid Parentheses — LeetCode 32. The hard variant.
# Trick: stack of INDICES, with sentinel -1 at the bottom.
def longest_valid(s):
    stack = [-1]                              # sentinel: "last unmatched closer"
    best = 0
    for i, ch in enumerate(s):
        if ch == '(':
            stack.append(i)
        else:                                  # ')'
            stack.pop()
            if not stack:
                stack.append(i)                # reset the sentinel
            else:
                best = max(best, i - stack[-1])
    return best
§07 · Pattern Deep Dive — BFS / Queue

Layer by layer. Shortest by construction.

BFS using a queue is the unique algorithm that, on an unweighted graph, computes shortest distances in O(V+E) time. The reason: the queue guarantees you process nodes in order of distance from the source. Every node is dequeued exactly once at its true minimum distance.

FIG. 06 · ANIMATEDBFS on a grid — wavefront expansion from the source
[INIT]5×8 grid. Source at (0,0). Watch the wavefront expand outward, one layer per step.
# BFS on a grid — shortest path from src to any cell
from collections import deque
def bfs_grid(grid, src):
    R, C = len(grid), len(grid[0])
    dist = [[-1] * C for _ in range(R)]
    q = deque([src])
    dist[src[0]][src[1]] = 0
    while q:
        r, c = q.popleft()
        for dr, dc in [(-1,0),(1,0),(0,-1),(0,1)]:
            nr, nc = r+dr, c+dc
            if 0<=nr<R and 0<=nc<C and dist[nr][nc]==-1 and grid[nr][nc] != '#':
                dist[nr][nc] = dist[r][c] + 1
                q.append((nr, nc))
    return dist

# Multi-source BFS — Rotting Oranges. Seed ALL rotten cells at once.
def rotting_oranges(grid):
    R, C = len(grid), len(grid[0])
    q = deque()
    fresh = 0
    for r in range(R):
        for c in range(C):
            if grid[r][c] == 2: q.append((r, c, 0))
            elif grid[r][c] == 1: fresh += 1
    minutes = 0
    while q:
        r, c, t = q.popleft()
        minutes = max(minutes, t)
        for dr, dc in [(-1,0),(1,0),(0,-1),(0,1)]:
            nr, nc = r+dr, c+dc
            if 0<=nr<R and 0<=nc<C and grid[nr][nc] == 1:
                grid[nr][nc] = 2
                fresh -= 1
                q.append((nr, nc, t + 1))
    return minutes if fresh == 0 else -1
Multi-source BFS is the elegant trick that converts what looks like N separate BFS runs into one. Seed the queue with all sources at distance 0. The wavefront naturally produces "minimum distance to any source" for free.
§08 · Pattern Deep Dive — Monotonic Deque

The structure that beats the heap.

For sliding-window-maximum, the obvious answer is a max-heap of size k — O(n log k). The senior answer is a monotonic deque — O(n). The deque holds indices in decreasing order of their values; the front is always the max of the current window.

FIG. 07 · ANIMATEDSliding Window Maximum — monotonic deque
[INIT]Array [1,3,-1,-3,5,3,6,7], k=3. Deque keeps indices monotonically decreasing in value.
# Sliding Window Maximum — LeetCode 239. O(n), beats the heap.
from collections import deque
def max_window(arr, k):
    dq = deque()         # indices, values monotonically DECREASING front-to-back
    res = []
    for i, v in enumerate(arr):
        # 1. evict indices outside the window
        while dq and dq[0] <= i - k:
            dq.popleft()
        # 2. maintain monotonicity from the back
        while dq and arr[dq[-1]] < v:
            dq.pop()
        # 3. append current
        dq.append(i)
        # 4. record window max once we have k elements
        if i >= k - 1:
            res.append(arr[dq[0]])
    return res
The amortized magic: each index is appended once and popped at most once, total work O(n). The heap version is O(n log k) — slower for large k. Mention this trade-off; it signals algorithmic maturity.
§09 · The Canon

Twelve problems. Solve these cold, you are ready.

01 · Valid ParenthesesEASY

Prompt: Determine if a string of brackets is balanced.

Pattern

Matching/balancing. Push openers; on closer, pop and verify match.

The most-asked easy stack question. Edge cases that trip candidates: empty string (valid), unmatched closer at start, unmatched opener at end. Always check that the stack is empty at the end.
02 · Min StackMEDIUM

Prompt: Design a stack with O(1) push, pop, top, and getMin.

Pattern

Auxiliary stack tracking running minimum.

Two solutions: (a) a parallel min-stack pushing the running min on every push; (b) a single stack storing (value, current_min) pairs. The second is more space-efficient if mins repeat. Mention both.
03 · Implement Queue using StacksEASY

Prompt: Build a FIFO queue using only stack operations.

Pattern

Two stacks: in for enqueue, out for dequeue. Move from in → out only when out is empty.

The amortized argument: each element is pushed and popped at most twice — O(1) amortized per operation. Articulate this; interviewers love amortized analysis.
04 · Daily TemperaturesMEDIUM

Prompt: For each day, how many days until a warmer day? 0 if no warmer day comes.

Pattern

Monotonic decreasing stack of indices.

Direct application of "next greater element." Storing indices (not values) is what lets you compute the day-distance.
05 · Largest Rectangle in HistogramHARD

Prompt: Given bar heights, find the area of the largest rectangle that fits.

Pattern

Monotonic increasing stack. Width formula: i − stack[-1] − 1.

Notoriously the gateway to senior-level loops. The sentinel trick (append a 0 height) flushes the stack at the end. Also extends to "Maximal Rectangle in 0/1 Matrix" — apply histogram row by row.
06 · Trapping Rain WaterHARD

Prompt: Given heights, compute total trapped water.

Pattern

Three valid approaches: DP arrays, monotonic stack, two-pointer.

Monotonic-stack version: pop on each new bar, compute trapped water as (min(left,right) − bottom) × width. Two-pointer is O(1) space; mention it as the optimal. Walk through both — that's a staff-level signal.
07 · Evaluate Reverse Polish NotationMEDIUM

Prompt: Evaluate an expression in postfix notation.

Pattern

Single stack of operands. On operator, pop two, apply, push result.

Watch the order of operands on subtraction and division: b = pop(); a = pop(); push(a − b). Reversing this is the bug everyone hits.
08 · Decode StringMEDIUM

Prompt: Given "3[a2[bc]]", return "abcbcabcbcabcbc".

Pattern

Two stacks (count + string), pushed on [, popped and combined on ].

The clean version uses one stack of (count, current_string) tuples. On [, push and reset. On ], pop and prepend.
09 · Sliding Window MaximumHARD

Prompt: For each window of size k, return the max.

Pattern

Monotonic deque. Front always holds current window max.

Heap solution is O(n log k); deque is O(n). Interviewers expect the deque solution at L5+. The three-step routine (evict out-of-window, maintain monotonicity, append) is worth memorizing verbatim.
10 · Binary Tree Level-Order TraversalMEDIUM

Prompt: Return tree nodes level by level.

Pattern

BFS with queue. Process nodes in batches of len(queue) per level.

The "process by level" trick is to record size = len(q) at the start of each iteration, then dequeue exactly size nodes. This separates levels cleanly.
11 · Rotting OrangesMEDIUM

Prompt: A grid of oranges; rotten ones rot adjacent fresh ones each minute. Return total minutes, or -1 if impossible.

Pattern

Multi-source BFS. Seed all rotten cells at time 0.

The "seed all sources at once" insight is the senior key. Naively running BFS from each rotten orange is O(R·V); multi-source is O(V).
12 · Basic CalculatorHARD

Prompt: Evaluate "(1+(4+5+2)-3)+(6+8)" with parentheses, +, −, and integers.

Pattern

Stack of (running_result, sign) pairs, pushed at ( and popped at ).

The clean trick: track result, sign, and a stack. On (, push (result, sign) and reset. On ), multiply current by previous sign and add to previous result. No recursion needed.
§10 · The Night-Before Cheat Sheet

If you forget everything else — remember this page.

First reflex
"What's pending?"

If something is unresolved, ask: stack (most recent) or queue (oldest first)?

Store indices
Not values

Sentinels flush the stack at end-of-array and remove special cases.

The monotonic-stack template — write this from memory tonight:

def monotonic_stack(arr):
    stack = []                     # indices
    res = [-1] * len(arr)
    for i, v in enumerate(arr):
        while stack and arr[stack[-1]] < v:   # or > for the other variant
            res[stack.pop()] = v   # or i, or v - arr[..], depending on the question
        stack.append(i)
    return res
