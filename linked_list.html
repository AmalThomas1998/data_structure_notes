§01 · The Mental Model

Arrays are where.
Linked lists are next.

An array is a street of townhouses — every home has a number, and if you want #47, you walk straight there. The cost of knowing "where" is paid upfront: memory must be contiguous, and inserting a new house between #3 and #4 requires shoving every subsequent house one plot over.

A linked list is a treasure hunt. Each clue tells you only where the next clue is. You cannot teleport to the 47th clue — you must walk. But you can splice a new clue between any two, instantly, for the price of rewriting two arrows.

Interviewers love linked lists not because they appear in production (they rarely do outside of kernels and allocators), but because the data structure forces you to think in pointers — and pointer manipulation is the crucible in which systems thinking is tested.

Why interviewers ask this

Linked-list questions test four things at once: reference semantics, edge-case discipline (empty, one node, two nodes, cycles), in-place mutation without aux memory, and the ability to draw on a whiteboard faster than you can code. A candidate who can reverse a list in-place while narrating invariants is signaling senior-level control.

i.

Node = Value + Arrow

Every node carries its payload and a single reference to "what comes next." That's it. The structure is defined entirely by a chain of these arrows.

ii.

The Head Owns the List

Lose the head pointer, lose the list — garbage collectors will reap everything. The head is the sole handle on the structure.

iii.

Null is the Period

A null next pointer is the terminal sentence. Any algorithm must answer: "what happens at null?" before it is correct.

iv.

You Never Have the Previous

In a singly linked list, knowing node X gives you no way back. This asymmetry is the source of every clever algorithm on this page.

§02 · Anatomy of a Node

Two fields. Infinite consequences.

Every algorithm in this codex is, at its heart, a choreography of which arrows to rewrite and in what order. Before you solve a single problem, you must be able to draw a node without thinking about it.

# Singly linked list — the canonical definition
class ListNode:
    def __init__(self, val=0, next=None):
        self.val  = val    # the payload
        self.next = next   # pointer to the NEXT node, or None

# Doubly linked list — adds a back-pointer (O(1) removal given a node ref)
class DListNode:
    def __init__(self, val=0):
        self.val  = val
        self.next = None
        self.prev = None   # the game-changer for LRU caches, deques

The three flavors you must recognize on sight

A

Singly Linked

One arrow forward. The default. Most interview problems assume this. Memory efficient, but you can never look back.

B

Doubly Linked

Arrows both ways. The secret ingredient in LRU Cache (the most-asked OOD question at Meta/Amazon/Uber). Enables O(1) removal when given a node.

C

Circular

Tail points back to head. Used in round-robin schedulers, Josephus problems, and any "next player" logic. Cycle detection becomes mandatory.

The dummy node trick — write this in your sleep

Roughly 70% of linked-list algorithms become shorter and bug-free when you prepend a dummy node before the real head. Why? It removes the special case "what if I'm inserting before the first element?" because there is always something before the first element. Return dummy.next instead of head. This one trick eliminates an entire class of off-by-one errors.

§03 · Core Operations

The five moves that everything is built from.

Before patterns, master primitives. If you can't insert and delete from any position with your eyes closed, pattern-based problems will collapse on you mid-interview. Below: an interactive node you can manipulate.

Operation cheat sheet

# 1. INSERT AT HEAD — O(1)
def insert_head(head, val):
    node = ListNode(val)
    node.next = head
    return node  # new head

# 2. INSERT AFTER A GIVEN NODE — O(1)
def insert_after(prev, val):
    node = ListNode(val)
    node.next = prev.next
    prev.next = node          # order matters! write next first, then link

# 3. DELETE A GIVEN NODE (with only that node, no prev) — O(1) trick
def delete_node(node):
    node.val  = node.next.val     # copy next's value into yourself
    node.next = node.next.next    # then skip next. You become next.

# 4. FIND LENGTH — O(n)
def length(head):
    n = 0
    while head:
        n += 1
        head = head.next
    return n

# 5. REVERSE IN PLACE — O(n) time, O(1) space. The most-asked 1-liner.
def reverse(head):
    prev, curr = None, head
    while curr:
        nxt = curr.next      # stash
        curr.next = prev     # flip
        prev = curr          # advance prev
        curr = nxt           # advance curr
    return prev             # new head
If you can reverse a linked list in place, on a whiteboard, while explaining your invariants out loud — you will pass the data-structures bar at any company on earth.
— paraphrased from a Google L5 hiring committee memo

§05 · Pattern Deep Dive — Fast & Slow

One pass. Two speeds. Every middle, end, and cycle.

The tortoise-and-hare pattern is the single highest-leverage technique in linked-list interviews. Master it and four separate classes of questions collapse into one.

Slow moves 1 step, fast moves 2 steps. When fast reaches the end, slow is at the middle. If they ever meet, a cycle exists. Offset fast by k steps and you find the k-th node from the end in one pass.

The mathematical punchline

If there is a cycle, fast gains one step on slow per iteration. Over any finite loop of length L, fast will overtake slow within L steps of slow entering the cycle. Meeting is guaranteed. The proof is pure modular arithmetic, and interviewers love a candidate who can gesture at it.

FIG. 03 · ANIMATEDFast & slow pointers — find the middle
[INIT] slow=0, fast=0. Press Step to advance.
# Find the middle of a linked list — O(n), O(1)
def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow  # for even length, returns the SECOND middle

# Detect cycle — O(n), O(1). Floyd's classic.
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast: return True
    return False

# Nth from end in ONE pass — offset fast by n, then walk together.
def nth_from_end(head, n):
    fast = head
    for _ in range(n): fast = fast.next
    slow = head
    while fast:
        slow, fast = slow.next, fast.next
    return slow

Why the offset trick works — geometric intuition

Imagine two runners on a track. The track has total length L nodes. Place slow at the start. Place fast exactly n steps ahead. Now both run at the same pace until fast falls off the end (hits null).

At that moment, fast has traveled L − n steps from its starting position. Since they ran in lockstep, slow has also traveled L − n steps from its start — landing at index L − n. That index is exactly the n-th node from the end.

The offset preserves the gap of n nodes between them. When fast reaches the end, slow is n nodes behind the end — which is what we wanted.

The "fence post" detail

To remove the n-th from the end, you usually want slow to land on the node before the target — so you can splice it out. The fix: start fast n+1 steps ahead, or use a dummy node. The off-by-one between "find the n-th" and "remove the n-th" is the most common mistake. Always draw it.

FIG. 04 · ANIMATEDNth from end — offset two pointers, walk together
[INIT]List of 7 nodes. Pick n, then Step. Phase 1: advance fast by n. Phase 2: walk both together until fast falls off.
Why this is harder than it looks: the candidate must reason about two pointer positions and a fixed offset between them — and prove the offset is preserved across the entire walk. Articulating "the gap of n nodes never changes once we enter phase 2" out loud is what convinces an interviewer you understand the algorithm, not just the code.
§06 · Pattern Deep Dive — Reversal

Three pointers. Nothing else.

Reversal is the other foundational pattern. The entire algorithm is three named variables — prev, curr, next — and a four-line loop. Once it is in your bones, the harder variants (reverse between positions m..n, reverse in groups of k) are just this loop with a wrapper.

FIG. 04 · ANIMATEDIn-place reversal — three pointer ballet
[INIT] prev=null, curr=head. We'll flip every arrow.
# The canonical iterative reversal. Memorize this.
def reverse(head):
    prev, curr = None, head
    while curr:
        nxt       = curr.next    # 1. save what's ahead
        curr.next = prev         # 2. flip the arrow backward
        prev      = curr         # 3. prev crawls forward
        curr      = nxt          # 4. curr crawls forward
    return prev                 # prev is the new head when curr=None

# Reverse nodes in k-groups — a FAANG favorite. Hard.
def reverse_k_group(head, k):
    dummy = ListNode(0, head)
    group_prev = dummy
    while True:
        kth = group_prev
        for _ in range(k):
            kth = kth.next
            if not kth: return dummy.next
        group_next = kth.next
        # reverse the segment (group_prev.next ... kth)
        prev, curr = group_next, group_prev.next
        while curr is not group_next:
            nxt = curr.next
            curr.next = prev
            prev = curr
            curr = nxt
        tmp = group_prev.next
        group_prev.next = kth
        group_prev = tmp
Senior insight: recursion for reversal is elegant but uses O(n) stack — mention it, but deliver the iterative version. Interviewers reward candidates who explicitly reason about stack vs heap.
§07 · Pattern Deep Dive — Floyd's Cycle

A cycle begins where math says it must.

Once you know a cycle exists, the follow-up question — "find the node where the cycle begins" — is a classic. The trick is counter-intuitive and deeply beautiful.

The two-phase algorithm

Phase 1: Detect — slow and fast meet inside the cycle.

Phase 2: Reset slow to the head. Move both one step at a time. Where they meet is the cycle's entry node.

The proof, in one line

Let F = distance from head to cycle start, a = distance from cycle start to meeting point, b = remaining cycle. Then 2(F+a) = F+a+b+a ⟹ F = b. Walking F steps from head and b from meeting point arrives at the same node.

FIG. 05 · ANIMATEDFloyd's cycle detection — tortoise catches hare
[INIT] Both pointers at head. Watch for the meeting.
# Find where the cycle begins — LeetCode 142
def detect_cycle(head):
    # Phase 1: meet inside the cycle
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast: break
    else:
        return None          # no cycle
    # Phase 2: reset slow, walk in lockstep
    slow = head
    while slow is not fast:
        slow = slow.next
        fast = fast.next
    return slow                # cycle entry
§08 · Pattern Deep Dive — Merging

Two streams, one river.

Merging two sorted lists is the quiet workhorse of this topic. It's the building block for merge-sort on a list, for the k-list merge (via min-heap), and a staple of "combine two data feeds" system-design questions.

FIG. 06 · ANIMATEDMerging two sorted lists with a dummy head
[INIT] Two sorted lists. Dummy node prepares the merged output.
# Merge two sorted lists — O(n+m), O(1)
def merge_two(l1, l2):
    dummy = tail = ListNode()
    while l1 and l2:
        if l1.val <= l2.val:
            tail.next, l1 = l1, l1.next
        else:
            tail.next, l2 = l2, l2.next
        tail = tail.next
    tail.next = l1 or l2      # attach whatever remains
    return dummy.next

# Merge K sorted lists — O(N log k) using a min-heap
import heapq
def merge_k(lists):
    heap = []
    for i, node in enumerate(lists):
        if node: heapq.heappush(heap, (node.val, i, node))
    dummy = tail = ListNode()
    while heap:
        _, i, node = heapq.heappop(heap)
        tail.next = node
        tail = tail.next
        if node.next: heapq.heappush(heap, (node.next.val, i, node.next))
    return dummy.next
§09 · The Canon

Ten problems. If you can solve these cold, you are ready.

Problem 01 · Reverse a Linked ListEASY

Prompt: Given the head of a singly linked list, reverse it and return the new head.

Pattern

In-place reversal (§06). Three-pointer loop.

Interviewer will almost certainly follow up: "now do it recursively." Be ready with both. Then: "what's the stack cost?" Answer: O(n).
Problem 02 · Linked List Cycle II (Find Entry)MEDIUM

Prompt: Return the node where the cycle begins. If there is no cycle, return null.

Pattern

Fast & slow, two-phase (§07).

The fact that F = b is what makes the two-phase trick work. Draw it. The mathematical elegance wins points.
Problem 03 · Remove Nth Node From EndMEDIUM

Prompt: Remove the n-th node from the end of the list in one pass.

Pattern

Dummy head + two walkers with an offset of n.

The dummy node handles the case where you remove the actual head. Without it, you need special-case code. With it, the algorithm is seven lines.
Problem 04 · Merge K Sorted ListsHARD

Prompt: Given k sorted linked lists, merge them into one sorted list.

Pattern

Hybrid: linked list + min-heap, or divide-and-conquer pairwise merge.

State both approaches. Heap is O(N log k) time, O(k) space. Divide-and-conquer is O(N log k) time, O(1) extra (plus recursion). If the interviewer says "what if a list is a stream?" — heap wins, because divide-and-conquer requires all heads upfront.
Problem 05 · Copy List with Random PointerMEDIUM

Prompt: Each node has a next and a random pointer. Deep-copy the list.

Pattern

Hash & point (§04, pattern 5). Two-pass with a dict, or three-pass in-place weaving.

The "O(1) extra space" version weaves clones into the original list (A → A' → B → B' …), sets random pointers via cur.random.next, then un-weaves. A genuinely clever trick that signals senior level.
Problem 06 · LRU CacheMEDIUM

Prompt: Design a data structure with O(1) get and put that evicts the least-recently-used key when capacity is reached.

Pattern

Hybrid: hashmap (key → node) + doubly linked list (ordering by recency).

This is the most-asked OOD question at large tech companies. The hashmap gives O(1) lookup. The doubly linked list gives O(1) move-to-front and O(1) eviction-from-tail. Use a sentinel head and tail to eliminate null checks.
Problem 07 · Reorder ListMEDIUM

Prompt: L0→L1→...→Ln becomes L0→Ln→L1→Ln-1→...

Pattern

Composition: find middle (fast/slow) → reverse second half → merge two halves alternately.

The test is whether you can stitch three patterns together in one problem. Every sub-step is a named primitive you should have memorized.
Problem 08 · Palindrome Linked ListEASY

Prompt: Determine if a linked list is a palindrome in O(n) time, O(1) space.

Pattern

Find middle → reverse second half → walk both halves comparing.

O(n) / O(1) is the trick. Naive is push to array and two-pointer — which is O(n) / O(n) and won't earn the full grade.
Problem 09 · Reverse Nodes in K-GroupHARD

Prompt: Reverse every k consecutive nodes. Left-over tail stays as is.

Pattern

In-place reversal applied in blocks, with boundary rewiring via a dummy.

This is the gateway problem between "knows reversal" and "masters reversal." Expect it for L5+ at Google, senior at Meta. Draw the boundary pointers before you write a line of code.
Problem 10 · Intersection of Two Linked ListsEASY

Prompt: Two lists may merge. Find the node of intersection in O(1) space.

Pattern

Two-pointer trick: when a reaches null, send it to headB; when b reaches null, send it to headA. They align because each pointer walks len(A) + len(B) total.

A candidate who derives this without hints is signaling mathematical maturity. The "swap heads at null" insight is the whole problem.
